## Что сделал агент

### Рецензия (устно, до правок)

Разбор концепт-документа и `readme.md` с выводом: концепция и архитектура сильные, но есть обещания, не выдерживающие проверки способом получения данных, и рассинхрон между документами. Ключевые находки:

1. **Chrome URL недостижим из заголовка окна.** Концепт-документ называл «минимальным вариантом» набор `URL / Title / Window / Tab index / Pinned / Active / Profile` — без расширения браузера это максимум. Реальные способы: UIA (best-effort, Chromium строит accessibility-дерево только по запросу AT-клиента), копия `History` (залочена, даёт историю, а не состояние), SNSS (закрытый формат), отладочный порт (нарушает zero-setup).
2. **Privacy-обещания не выполнены.** «Банковские сайты» требуют URL (который не всегда есть), «приватные окна» не детектируются надёжно в принципе.
3. **Не назван источник «изменённых файлов».** `Files: 12 modified` без драйвера и админки берётся из `git status --porcelain --no-optional-locks`, `FileSystemWatcher`, `Recent\*.lnk`, `User/History`.
4. **VS Code adapter по заголовкам — слабый путь.** Есть локальные источники фактов: `state.vscdb`, `User/History/*/entries.json`, `workspaceStorage/*/workspace.json`.
5. **WinForms в концепт-документе vs WPF в `readme.md` и csproj.**
6. **Стрелка слоёв перевёрнута:** `Core → Infrastructure` означало зависимость ядра от инфраструктуры.
7. **Слои не обеспечены structurally:** один csproj = правило является комментарием.
8. **Session не определена** формально; нет crash-recovery; не учтено окно `WM_QUERYENDSESSION` (~5 с).
9. **«Где я остановился?» — флагманская фича без алгоритма**, только mock-вывод.
10. **Схема БД неполна:** нет `applications`, `restore_plans`/`restore_steps`, `file_activity`, `settings`; дублирование `summary_json` с реляционными таблицами; не ограничен объём `events`.
11. **Нет бюджета ресурсов**, tray, автозапуска, демо-режима, prior art, тестов.
12. **Проценты в scoring необоснованны:** `100% / 5%` не выводится из весов `+50/+40/+30`.
13. **Риск `PublishSingleFile`** на учебном ПК: распаковка нативных либ в temp, «unable to load e_sqlite3», AppLocker/антивирус, медленный первый запуск.
14. **`ExecuteCommand` из БД — выполнение произвольного кода**, если снапшот подделан.
15. **Пути запуска приложений** (`code`, `wt`, `chrome`) могут отсутствовать в PATH — Restore упадёт на чужом ПК.
16. **Project не определён**, хотя это ядро Context Engine.
17. **Must-пункты без шагов:** системные события, privacy, retention, Chrome, tray, демо, тесты.

### Решения (коротко)

1. **Единственный источник истины по скоупу — `readme.md`.** Концепт-документ переведён в роль мотивации/концепции/границ; порядок шагов и схема БД из него убраны, чтобы документы не разъезжались. Приоритет зафиксирован в шапке: `readme.md` → `docs/specs/*` → концепт-документ.
2. **Chrome: title всегда, URL opportunistically через UIA** с флагом `url_available`. Точный список всех вкладок всех окон — явный non-goal.
3. **Incognito не обещается.** Формулировка для UI и защиты: гарантия не-записи достигается исключением приложения целиком.
4. **«Изменённые файлы» = `git status --porcelain --no-optional-locks`** как основной источник; `--no-optional-locks` обязателен, сетевые git-команды запрещены, `GIT_TERMINAL_PROMPT=0` обязателен (иначе фоновый процесс может показать окно ввода пароля).
5. **VS Code adapter переведён на чтение фактов** (`state.vscdb`, `entries.json`), заголовок окна — только fallback с `source = 'window_title'`.
6. **CWD терминала: базовый путь CIM `CommandLine`**, PEB — опциональный Tier 2 с обязательным fallback из-за AppContainer в Store-версии Terminal. Поле `source` различает «запущен в X» и «сейчас в X».
7. **Проценты убраны из MVP.** Только жёсткие правила (равенство git root, каталога, принадлежность снапшоту). Веса — после замеров.
8. **Схема БД перекроена:** добавлены `applications`, `file_activity`, `restore_plans`, `restore_steps`, `settings`, `browser_tabs`; правило разделения «в таблицы — то, по чему запросы, остальное — в `summary_json`», дублирование факта запрещено; `schema_version` внутри снапшота.
9. **Событие пишется на изменение, не на тик.** Иначе при опросе раз в секунду ~86k строк в сутки.
10. **`StoppedEngine` выделен в отдельный движок** с таблицей истинности — именно она доказывает тезис «детерминированно, без LLM» и покрывается тестами.
11. **RestorePlan получил три обязательных свойства:** порядок (хост → окно → файлы/URL), идемпотентность, dry-run.
12. **`ExecuteCommand` только по whitelist** (`code -g`, `wt -d`, read-only git). Полная поддержка — после появления подписи планов.
13. **Privacy-конвейер перенесён до первой записи в БД** (шаг 1), а не к `SettingsWindow` (шаг 9).
14. **Два проекта:** `Continuum.Core` (`net10.0`, без WinAPI и WPF) и `Continuum.App` (`net10.0-windows`) — свойство становится проверяемым, а не комментарием.
15. **`--demo` с отдельной БД** как страховка защиты; добавлен чек-лист рисков на чужом ПК с запасным путём на каждый пункт.
16. **Folder-publish вместо single-file** для демо-сборки; `IncludeNativeLibrariesForSelfExtract=true`, если single-file всё же нужен; сброс состояния удаляет `-wal`/`-shm`.
17. **Tray + автозапуск через HKCU** добавлены в Must: фоновый рекордер не должен занимать окно, а HKCU не нарушает zero-admin (запрещён HKLM).
18. **Классы надёжности A/B/C** введены в `data-sources.md`, чтобы способ обработки отказа был специфицирован, а не импровизирован.

## Что НЕ сделано / отложено

- **Код не тронут.** `Continuum.csproj` по-прежнему один проект, `MainWindow` пуст. Разделение на `Continuum.Core` / `Continuum.App` (шаг 0) — следующая задача, в этой сессии не выполнялась.
- **Схема БД не применена** — SQL в `readme.md` остаётся драфтом до шага 1; миграции и `PRAGMA user_version` не созданы.
- **Список менеджеров паролей и банковских клиентов** в `privacy-pipeline.md` §4.1 предзаполнен частично; полные списки — на шаге 9 вместе с `SettingsWindow`.
- **Тесты не написаны** — в `privacy-pipeline.md` §9 и `readme.md` (шаг 8) зафиксирован только обязательный набор.
- **Веса скоринга не измерялись** — сознательно отложены до рабочего вертикального среза.

## Уточнения, внесённые после первой записи

При проверке согласованности обнаружено, что документация опережала фактическое состояние репозитория в двух местах, и исправлено:

- `readme.md` §«Архитектура»: дерево проектов начиналось с `Continuum.sln`, хотя в репозитории `Continuum.slnx` и один проект. Добавлена пометка «Целевая структура» с указанием, что разделение выполняется на шаге 0.
- `readme.md` §«Запуск и сборка»: команды `dotnet run --project Continuum.App` и `dotnet publish Continuum.App` не работают до шага 0. Раздел разделён на «Сейчас (один проект)» и «После шага 0 (два проекта)»; `dotnet test` помечен как появляющийся вместе с `Continuum.Tests` на шаге 8.

Принцип: readme описывает целевое состояние, но обязан явно отмечать, где оно ещё не достигнуто. Иначе документ становится инструкцией, которая не работает.
